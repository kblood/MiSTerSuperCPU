1. **Q1: off by one.** With edge `N` = CPU advances and presents new line `L`: after `N`, `rp_cache_hit(L)=1` but `line_word` is still old. At edge `N+1`, `line_word` is updated to `L`, but `rp_cache_di_d1` samples the pre-edge stale `rp_cache_di`. So `hit_d1=1` while `di_d1` is still stale for cycle `N+1..N+2`. Correct `di_d1` appears only after edge `N+2`. Your “co-phased” claim is false. See [cpu_cache.vhd](C:/LLM/C64/MiSTerSuperCPU/C64_MiSTer/rtl/cpu_cache.vhd:276) and [cpu_cache.vhd](C:/LLM/C64/MiSTerSuperCPU/C64_MiSTer/rtl/cpu_cache.vhd:284).

2. **Q2: predictor is only safe if cpu_cyc is never first-cycle-after-enable.** `sdram_busy_cnt` samples `sdram_hit_pred` on the `cpu_cyc` edge, not on `enableCpu_816` [fpga64_sid_iec.vhd](C:/LLM/C64/MiSTerSuperCPU/C64_MiSTer/rtl/fpga64_sid_iec.vhd:3449). If current cadence gives address at `N` and grant at `N+2`, registered hit is okay. If grant can occur at `N+1`, the process sees old `hit_d1` because VHDL updates happen after the edge. That would short-grant the wrong access. Prove slot alignment, don’t assume it.

3. **Q3: keep fill qualified by current combinational hit.** Moving fill to `hit_d1` risks suppressing a real miss after a prior hit. Current `rp_fill_we` uses current `rp_cache_hit` [fpga64_sid_iec.vhd](C:/LLM/C64/MiSTerSuperCPU/C64_MiSTer/rtl/fpga64_sid_iec.vhd:4880), which is the right miss classifier. Bigger hazard: `fill_data => cpuDi` still feeds the post-override mux [fpga64_sid_iec.vhd](C:/LLM/C64/MiSTerSuperCPU/C64_MiSTer/rtl/fpga64_sid_iec.vhd:4895). Any stale `hit_d1=1` during a miss fill writes cache data into the miss line. Prefer a pre-cache normal-bus fill-data signal.

4. **Q4: yes, stale-address window exists.** Immediately after enable at `N`, CPU address has moved to access `B`, but `hit_d1/di_d1` can still describe access `A` until at least `N+1`, and `di_d1` may be stale until `N+2`. CPU probably does not latch `B` until later under 4-apart cadence, but `cpuDi` is globally wrong during that window [fpga64_sid_iec.vhd](C:/LLM/C64/MiSTerSuperCPU/C64_MiSTer/rtl/fpga64_sid_iec.vhd:1965).

5. **Q5: STA should improve, but the forced probe can still fail if constraints still target CPU internals broadly.** Registering both select and data cuts the known `tag_mem/cache_di -> cpuDi -> P65C816` path. Remaining risks are the wide `cpuDi` priority mux and `rp_cache_hit_d1` select into CPU combinational logic, not the M10K `line_word` path. Also verify the new `rp_cache_di -> rp_cache_di_d1` input path separately.
