## Fixes Applied

### 1. REU DMA ram_active (reu.v, c64.sv)
**Root cause**: The SDRAM mux routed REU address/we/din using `reu_ram_we`
and `ext_cycle` conditions. For FETCH (REU read → C64 write):
- Reads used wrong SDRAM address (`reu_ram_we=0`, `ext_cycle=0` at CPUC
  → fell through to `scpu_sdram_addr`)
- C64 bus writes were suppressed (`cart_we` overridden by `reu_ram_we=0`)

**Fix**: Added `ram_active` output to `reu.v` that's HIGH only during
STATE_PROC_RAM. The SDRAM mux uses it to cleanly separate SDRAM phases
(REU addr/we/din) from bus phases (normal cart signals).

**Verified**: BASIC POKE $58 → STASH → clear → FETCH → PEEK returns $58.

### 2. scpu_sdram_addr: cpu_has_bus gate (c64.sv, fpga64_sid_iec.vhd)
**Root cause**: `supercpu_cycle` (which includes `cpu_cyc`, `cs_ram`,
and `cpuHasBus`) was too restrictive — the combinational chain from
buslogic → cs_ram → cpu_cyc → supercpu_cycle could evaluate `'0'`
during data access cycles, causing LDA/STA long to read from `cart_addr`
(bank $00) instead of `scpu_superram_addr`.

Removing `supercpu_cycle` entirely fixed non-bank-$00 reads but allowed
VIC reads (VIC0 phase) to go to SuperRAM when `supercpu_bank` retained
a non-$00 value from the last CPU instruction.

**Fix**: Export `cpuHasBus` as `cpu_has_bus` port. Gate `scpu_sdram_addr`
on `supercpu_bank != $00 AND cpu_has_bus` — no `supercpu_cycle` needed.

### 3. Write-back buffer bank gate (fpga64_sid_iec.vhd)
**Root cause**: The write-back buffer stores only 16-bit addresses (no
bank byte). When `wb_drain_active` fired during non-bank-$00 cycles,
`ramAddr` was overridden with the 16-bit `wb_addr`, bypassing the
`scpu_superram_addr` calculation. Writes intended for SuperRAM went to
bank $00 SDRAM instead.

**Fix**: Gate `wb_drain_active` on `cache_cpu_bank = x"00"`. The write
buffer only drains during bank $00 cache hits, which is correct since
the buffer contents are always bank $00 data.

### 4. Turbo SDRAM slot bank restriction (fpga64_sid_iec.vhd)
**Root cause**: VIC0 SDRAM reads (cycle 12) update `dout_r` before
`enableCpu` fires for turbo slot reads (CPU0/CPU4/CPU8 at cycles
16/20/24). For bank $00, BRAM/cache hits mask this by delivering data
directly and cancelling the SDRAM pipeline. For SuperRAM ($01-$EF),
no BRAM/cache entries exist on cold access, so the CPU reads stale
VIC data from `dout_r`.

**Fix**: Gate turbo slots on `(cache_cpu_bank = x"00" OR >= x"F0")`.
SuperRAM accesses use CPUC only (16-cycle gap from VIC0 = enough time).
ROM banks ($F0+) are exempt because their data comes from ROM BRAM,
not SDRAM — `enableCpu` just acts as a timing advance signal.

## What Doesn't Work

### Doom Game Crash (~50s)
After ~50 seconds of game code execution (decompressing data from
SuperRAM with visible border color cycling through multiple phases),
the game crashes to a lowercase "ready." BASIC prompt. The crash
could be caused by:
1. **65816 native mode instruction bug** — REP/SEP/16-bit operations,
   MVN/MVP block moves, or other advanced opcodes
2. **SDRAM timing at CPUC** — the CPUC-only path for SuperRAM reads
   might still have timing margin issues
3. **Missing SuperCPU hardware features** — the real SuperCPU has
   SIMM SRAM with zero-wait-state access; our SDRAM has latency

### SuperRAM Data Access Mismatch
LDA long from bank $02 returns different data ($6A) than REU FETCH
from the same address ($78), neither matching the STASHed value ($58).
The `cpu_has_bus` and turbo slot fixes improved this but the exact
root cause of the remaining mismatch needs investigation.

## Architecture Changes

```
SDRAM Address Mux (c64.sv):
  Before: scpu_sdram_addr gated on supercpu_cycle (cpu_cyc+cs_ram+cpuHasBus)
  After:  scpu_sdram_addr gated on (supercpu_bank != $00) AND cpu_has_bus

REU DMA Path (reu.v → c64.sv):
  Before: SDRAM mux used reu_ram_we/ext_cycle for REU routing
  After:  SDRAM mux uses ram_active (HIGH only during STATE_PROC_RAM)

Write-Back Buffer (fpga64_sid_iec.vhd):
  Before: wb_drain_active fires on any cache_hit + wb_pending
  After:  wb_drain_active requires cache_cpu_bank = $00

Turbo SDRAM Slots (fpga64_sid_iec.vhd):
  Before: CPU0/CPU4/CPU8 fire for all banks
  After:  CPU0/CPU4/CPU8 fire only for bank $00 and $F0+
          SuperRAM ($01-$EF) uses CPUC only

Bus Cycle Allocation (32 slots per rotation):
  EXT0-3:  Cache hits (bank $00 only)
  DMA0-3:  REU DMA
  EXT4-7:  Cache hits (bank $00 only)
  VIC0-3:  VIC reads only
  CPU0-F:  Bank $00: BRAM/cache hits + SDRAM turbo
           SuperRAM: SDRAM at CPUC only
           ROM $F0+: SDRAM turbo (data from ROM BRAM)
```
