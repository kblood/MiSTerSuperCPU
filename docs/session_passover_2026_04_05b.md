## Session Summary
Continued debugging Doom display issue. Made major progress understanding the game's architecture and identified the root cause of why the CPU ends up in empty bank $9B.

## Key Findings

### 1. VIC IRQ Display Inversion (Minor)
The `!`/`.` suffix in UART output is INVERTED:
- `!` = VIC IRQ NOT asserted (irq_vic=1, active-low)
- `.` = VIC IRQ IS asserted
Path: c64.sv:1929 `~dbg_diag[7]` double-inverts the active-low signal.

### 2. Bank $9B is ALL ZEROS in doom.reu
The CPU executes at K:$9B, but bank $9B in the REU file has zero non-zero bytes. The CPU is executing an infinite stream of BRK ($00) instructions, advancing PC by 2 each cycle ($912A per frame).

### 3. REU = SuperRAM in SDRAM (No Copy Needed)
On MiSTer, REU and SuperRAM share the SAME SDRAM region:
- REU base: SDRAM $1000000
- SuperRAM bank B, addr A: SDRAM $1000000 + B*$10000 + A
- REU offset X: SDRAM $1000000 + X
These are identical! The loader.prg's REU→SuperRAM copy is redundant.

### 4. Game Data Map
Banks with data in doom.reu:
- $02-$03: computed data tables (generated by init)
- $07: graphics data
- $20-$2D: main game code (MIPS→65816 recompiled)
- $3F-$87: game assets/data
- $FF: bank allocation bitmap (metadata for loader)
- Banks $00-$01, $04-$06, $08-$1F, $88-$FE: EMPTY

### 5. Loader.prg Analysis
The 254-byte loader.prg (at $0801, BASIC SYS 2061):
1. Clears screen ($0400-$07FF with $20)
2. Relocates loader code to $0700
3. REU DMA: reads 256-byte metadata from REU $FF0000 → $0400
4. For each bank: checks metadata byte, copies REU→SuperRAM via STA [dp],Y
5. JML [$04FC] to game entry point from metadata

Metadata at REU $FF:BB:00 is bank allocation bitmap (which pages have data).
Entry point at $04FC from first DMA block.

### 6. Init Code at $20:0000
The game init:
1. SEI, CLD, CLC, XCE (native mode), set D=$0000, S=$01FF
2. Disables all interrupts (CIA, VIC)
3. Sets $01=$35, $D07E (hwenable), $D07B (turbo), $D07F (hwenable off)
4. Sets up 16 bank pointers in DP for decompression target banks $10-$1F
5. Runs computational decompression loop (65536 iterations, generates data for 16 banks)
6. NO BRK calls in early init — all direct code

### 7. BRK Dispatch Problem (ROOT CAUSE)
The game uses BRK #$nn as a supervisor call mechanism (MIPS SYSCALL equivalent).
Our BRK handler was RTI ($FF00), making every BRK a 2-byte NOP.
After init completes (successfully, since it doesn't use BRK), the game starts
using BRK for runtime calls. Since BRK returns garbage register values (unchanged
from before BRK), computed JML targets get wrong bank bytes → CPU jumps to empty
bank $9B → infinite BRK loop on zeros.

**Fix applied**: Changed BRK vector from $FF00 (RTI) to $FF04 (zero-regs handler):
```
$FF04: REP #$30     ; 16-bit A, X, Y
$FF06: LDA #$0000   ; A = 0
$FF09: TAX          ; X = 0
$FF0A: TAY          ; Y = 0
$FF0B: RTI          ; return with zeroed registers
```
This ensures BRK calls return $0000 in A/X/Y instead of random values.
Bank $00 is always valid (BRAM), so JMLs using A as bank byte go to bank $00.

### 8. IRQ Handler Architecture (Doom)
Doom's VIC raster IRQ chain:
1. IRQ vector $FFEE/$FFEF → $0D3C (trampoline in bank $00 SRAM, but not installed)
2. Trampoline → $80:0B17 (handler prologue)
3. Prologue: PHA/PHX/PHY/PHD/PHB, set D=$0000, DBR=$00, save/set $01=$35
4. Ack VIC IRQ ($D019=$FF)
5. JMP ($1D00) — indirect through bank $00 dispatch pointer
6. Dispatch pointer → $80:0D6C → JML [$00FC] (another level of indirection)
7. Handler body: VIC register writes for raster display

Our ROM stub:
- IRQ vector $FFEE/$FFEF → $FF20 (JML trampoline)
- $FF20: JML $800900 → WRONG! This skips the prologue (no DBR=$00 setup)
- Should jump to $80:0B17 (full prologue) — but $1D00 and $00FC pointers not set

### 9. SuperRAM Write Verification
Confirmed SuperRAM writes work correctly:
- Non-bank-$00 accesses don't trigger bram_hit or cache_hit
- enableCpu only fires from SDRAM pipeline (CPU SDRAM slots)
- ramWE = systemWe during CPU slots → writes reach SDRAM
- Write buffer is bank-$00 only, but SuperRAM doesn't need it

## UART Debug Format
`A:xxxx K:xx B:xx S:xxxx P:xx I:xx E:x F:xxxx T:xx C:xxxx N:xxxx V:xxxxWbbdd!`
- `!` = VIC IRQ NOT asserted (inverted display!)
