## LDA Long SuperRAM Bug — Root Cause & Fix

**Symptom**: `LDA $020100` returned `$10` (value at C64 RAM $0100, the stack
page) instead of the correct SuperRAM data. Deterministic, every run.

**Root cause**: The SDRAM address mux (`scpu_sdram_addr`) was registered at
clk32 to fix timing violations. This introduced a 1-cycle latency. When
LDA long transitions the bank byte from $00 to $02 for the data read phase,
`scpu_sdram_active_r` was still 0 (from the previous cycle when bank was $00).
The mux fell through to `cart_addr`, reading bank $00 SDRAM instead of SuperRAM.

**Why MVN worked**: MVN stays in the destination bank for multiple cycles
during the block move loop. By the time `cpu_cyc` fires, the registered
address had already updated. LDA long changes bank for just ONE cycle.

**Fix**: Reverted `scpu_sdram_addr` to combinational (no registration).
The -16ns timing violation on clk64 was NOT causing wrong data — the
registration latency was. The combinational version correctly routes to
SuperRAM on the same cycle the bank byte changes.

**Verification**:
- Looping LDA long test (scpu_lda_long_loop.s): GREEN border, returns $A5
- MVN test: Test 5 now shows $A5 (SuperRAM data) instead of $10

## All Changes This Session

### 1. SuperRAM Turbo Slots (fpga64_sid_iec.vhd)
- Removed bank gate from CPU0/CPU4/CPU8 turbo slots — all banks now allowed
- Added 3-stage SDRAM pipeline for SuperRAM (banks $01-$EF):
  `superram_enable_delay` gives SDRAM one extra clk32 cycle
- Added `superram_enable_delay` to BRAM and cache hit guards

### 2. SuperRAM Data Bypass (fpga64_sid_iec.vhd, c64.sv)
- Added `sdram_raw` port: direct SDRAM dout bypasses cartridge module
- `superram_data_r` latch: captures sdram_raw at enableCpu time
- cpuDi mux: `superram_data_r` has priority for SuperRAM reads

### 3. $D078 BRAM Flush (fpga64_sid_iec.vhd)
- `cache_flush_sw` now also clears `bram_pgvalid` and triggers
  `bram_valid_clearing`, so externally-loaded code (mbc load_rom)
  isn't masked by stale BRAM data

### 4. XCE Fix (P65C816.vhd, from iigs_simulation)
- Changed XCE SP/X/Y forcing condition from `P(0)='1'` to
  `(P(0)='1' or P(8)='1')` — covers both native→emulation and
  emulation→native transitions
- Ported from github.com/pcornier/iigs_simulation commit 374d004

### 5. SDRAM Address Mux Fix (c64.sv)
- Reverted `scpu_sdram_addr` from registered to combinational
- The 1-cycle registration latency caused LDA long to read bank $00

## Architecture Changes

```
SDRAM Address Mux (c64.sv):
  Before: Registered at clk32 (1-cycle latency, broke LDA long)
  After:  Combinational (correct on same cycle as bank transition)

SuperRAM Data Path (fpga64_sid_iec.vhd):
  Added: sdram_raw → superram_data_r latch → cpuDi mux bypass
  Purpose: Ensures correct SDRAM data reaches CPU despite buslogic
           cpuHasBus transitions at CPUF boundary

SDRAM Pipeline (fpga64_sid_iec.vhd):
  Bank $00/ROM: 2-stage (cpu_cyc → enableCpu, 2 clk32)
  SuperRAM:     3-stage (cpu_cyc → superram_enable_delay → enableCpu, 3 clk32)
  Guards:       BRAM and cache hit guards include superram_enable_delay

$D078 Cache Flush (fpga64_sid_iec.vhd):
  Before: Cleared 8KB instruction cache only
  After:  Also clears BRAM page valid bits (bram_pgvalid)

P65C816 XCE (P65C816.vhd):
  Before: Force SP/X/Y only when P(0)=1 (carry)
  After:  Force when P(0)=1 OR P(8)=1 (carry OR emulation)
```
