# SuperCPU Progress Report — 2026-03-19

## Current State

The MiSTer C64 SuperCPU core boots, runs the SuperCPU kickstart ROM, enters
65C816 emulation and native mode, and passes all register tests. The turbo
cache provides ~4MHz effective speed (vs 1MHz stock). Build: 73% ALMs, 90% M10K.

## What Works

### Core Features
- 65C816 CPU (P65C816 core) with emulation and native mode
- SuperCPU kickstart ROM boots C64 KERNAL correctly
- 8KB instruction cache (1024 lines × 8 bytes, wide 64-bit lines)
- 32KB dual-port BRAM for VIC zero-contention reads
- Turbo mode: ~4MHz effective (8 cache hits + 4 SDRAM reads per rotation)
- All SuperCPU speed registers ($D07A/B, $D072/3, $D074-77)

### Register Compatibility (10/10 tests pass)
- $D0BC SuperCPU detect (computed value, not static)
- $D0B0 mode detect ($40 = SCPU v2 C64 mode)
- $D07E/$D07F register enable/disable gating
- $D07A/$D07B software speed switching
- $D0B8 combined 1MHz status (software OR system)
- $D072/$D073 system 1MHz enable/disable
- $D074-$D077 optimization modes + $D0B4 readback
- CLC/XCE native mode enter/exit
- $D0B6 emulation mode flag
- 16-bit accumulator (REP #$20, LDA #$1234)

### IEC Bus Compatibility
- Auto-slowdown on CIA2 writes ($DD00-$DD03) AND reads ($DD00)
- Custom fastloaders work (SCPU Kicks demo loads from disk)
- 32ms timeout with auto-re-arm on repeated IEC access

### Tooling
- `tools/mister_debug.py`: deploy, screenshot, UART, PRG load, keys
- PRG autoloading via MGL (fixed: must use absolute paths)
- cc65/ca65 v2.19 installed with `--cpu 65816` support
- Test programs: `scpu_native_test.s` (15 native mode tests),
  `scpu_speed_bench.s` (4-mode speed comparison)
- Python test generators: `gen_scpu_regtest.py` and others

## What Doesn't Work Yet

### Same-Line Cache Suppress-Skip
The wide cache lines (8 parallel M10K banks) are in place and the `same_line`
detection signal is wired, but using it to skip the 1-cycle suppress caused
a boot crash. The combinational `cache_di` byte-select MUX output likely
has a timing race with `enableCpu`. This is the biggest performance blocker —
fixing it would double throughput from ~8MHz to ~16MHz for sequential code.

### DMAGic Hardware DMA Controller
The SuperCPU's DMA controller is not implemented. The SCPU Kicks demo loads
and shows its title screen but stalls at $82E0 waiting for DMA completion.
Many advanced SuperCPU demos and games (Doom, Wolf3D) need this.

### Raster Bar Jitter
VIC color register writes at turbo speed show ±3 pixel horizontal jitter
from variable `io_enable`/`cs_vic` timing. Fix must be in the bus logic
(`fpga64_sid_iec.vhd` io_enable path), NOT inside the VIC-II core.
Modifying `video_vicII_656x.vhd` color register latching breaks all colors.

### OSD Config Persistence Through MGL
Loading PRGs via MGL resets OSD settings, disabling SuperCPU/UART.
Workaround: write C64.cfg before MGL load, or manually re-enable via OSD.

## Architecture Research Findings (2026-03-18)

### Priority Path to 20MHz
1. **Fix same-line suppress-skip** — 0 M10K cost, up to 2x throughput
2. **SDRAM burst mode** — modify sdram.v for burst-of-4, 8x faster cache fills
3. **16KB cache** — +8 M10K blocks (risky at 91%), marginal benefit
4. **SuperRAM SDRAM banking** — already implemented, needs CRT/TAP conflict fix

### Community Feedback
- Real SuperCPU has 128KB fast SRAM (not SDRAM) — our cache+BRAM approximates this
- M10K: big buffers (cache data, BRAM). MLAB: fast small buffers (cache tags)
- SuperRAM SIMM was likely NOT 20MHz — CPU ran from fast SRAM, SIMM had wait states
- SDRAM address mux in official C64 core shows time-sharing pattern for multiple masters
